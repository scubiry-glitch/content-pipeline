一、产品需求文档（PRD）

1.1 产品概述

产品名称：内容生产流水线（Content Pipeline，内部称 paper）

一句话定位：面向行业研究与内容团队的一站式 AI 内容生产平台——从选题、研究、写作、评审到发布全流程自动化，并沉淀为可复用的知识底座（素材库、专家库、内容库、会议纪要库）。

核心价值：

  • 提效：选题评估、深度研究、文稿生成、多轮评审全 AI 驱动，人工只做决策与修订；
  • 提质：质量输入体系（事实核查、合规、蓝军评审、串行评审、数据交叉验证）保证输出可靠性；
  • 沉淀：把每一次生产过程中的知识（事实、专家观点、会议决策）结构化入库，越用越聪明；
  • 决策：CEO 驾驶舱与内容效果预测，让「写什么、怎么写、何时发」有数据依据。

线上地址：http://paper.morning.rocks（API 前缀 /api，前端 SPA + 同域 API 反代）

1.5 核心功能模块

① 内容生产流水线（production）

产品主线。任务按 5 阶段推进：选题评估 → 深度研究 → 大纲（专家评审 + 对话修订）→ 文稿生成（版本树/差异/回滚）→ 蓝军评审（单轮/串行/多轮）→ 定稿。支持任一阶段重做、任务隐藏/归档、数据核查与交叉验证。文稿支持 SSE 流式生成。

② 素材与资产（assets + quality）

素材库：上传、检索、主题分组、目录绑定、标签。质量输入体系：RSS 源管理、资讯抓取、条目打分、回收站；热点话题（RSS + 小红书/微博/知乎热榜，跨平台归并、核验、热度重算）；质量报告解析。

③ 专家库（expert-library）

Cognitive Digital Twin：专家画像（Profile）+ 知识库 + 心智模型图谱 + 辩论 + 调度 + 热点观点。核心接口 invoke（单次专家任务）、chat/stream（对话）、match（匹配）、review-outline（大纲评审）。反馈与校准闭环持续迭代专家表现。

④ 内容库（content-library，v7.0）

结构化记忆：从素材提取事实（Facts）→ 构建实体图谱（Entities）→ 信念演化（Beliefs）→ 共识与矛盾检测 → 跨域关联 → 自动生成维基。支持重新提取任务、信息增量报告（6h）、保鲜度检查（24h）、Zep 同步。

⑤ 会议纪要（meeting-notes）

一库多视图：会议本体（16 轴分析、决策质量、情绪曲线、必要性审计、偏差检测）、人物（承诺/盲点/LLM 画像）、Scope（项目/客户/话题，决策/假设/风险清单）、Runs（分析任务，可取消/恢复/抢救）、跨会议纵向分析与跨轴线索。外部系统可上传文件自动触发解析+分析，两段式回调。

⑥ CEO 决策驾驶舱（ceo）

双模主壳 + 6 房间 + Panorama + 外脑图书馆。跨模块聚合（会议纪要、专家库、内容库），按 Scope 预填，支持流式 run。会议解析后自动入队 g1 分析。

⑦ 合规 / 编排 / Stage3 / 预测 / Copilot / i18n（v4.x）

敏感词/广告法/版权/隐私检测与 AI 修复；条件触发编排规则；可视化标注 + 对话式修改 + 版本对比；传播潜力预测与排期；自然语言配置的智能助手与技能体系；术语库 + 翻译记忆的多语言翻译。

⑧ 支撑体系

多租户工作区、账号/OAuth、管理审计、收藏、情感分析（MSI 市场情绪指数）、统一领域 taxonomy、LLM 网关（OpenAI 兼容转发 + 模型配置）、LangGraph 流水线、AI 批量处理（RSS/素材）。

1.6 核心业务流程

流程 A：内容生产（5 阶段状态机）

创建任务（POST /production/，支持 topic + source_materials）
  → Stage1 选题评估（evaluate-topic：热点/竞争/可行性）
  → Stage2 深度研究（research：源配置 → 采集 → 资料库）
  → Stage3 大纲（planning 流式生成 → outline/expert-review 专家评审
        → outline-chat 对话修订 → outline/confirm）
  → Stage4 文稿（draft/generate-stream SSE 生成 → 版本树/差异/回滚
        → data-review 数据核查 → cross-validate 交叉验证）
  → Stage5 评审（reviews 蓝军 → review-items/decide 决策 → 串行评审可选
        → apply-revisions 应用修订 → finalize 定稿 → outputs 下载）
任意阶段可 redo/* 重做；全程可 compliance/check 合规检查。

流程 B：会议纪要外部接入（两段式）

外部系统 ──POST upload-task（file + callbackUrl）──▶ 系统
  1) 入库 + 自动解析 → 触发 16 轴分析 run（mode=api-oneshot）
  2) webhook① meeting_notes.uploaded（飞书卡片「📋 会议纪要已上传」，含 assets[].runId）
  3) 分析完成 → webhook② meeting_notes.analysis.completed
     （飞书卡片「🧠 会议分析已完成」，含 sharedUrl + 摘要）
  4) 分享链接 /shared/:token 可免登录查看

流程 C：内容库知识沉淀

素材入库 → extract（事实提取）→ facts/entities/beliefs 结构化
  → 6h 增量报告 delta / 24h 保鲜度 freshness/stale
  → consensus（共识）/ contradictions（矛盾）/ cross-domain（跨域）
  → synthesize 多源融合成文 / wiki/generate 维基条目
  → 供流水线 research 阶段检索引用（搜索/推荐/卡片）

1.7 数据与集成

  • 数据库：PostgreSQL author 库，按模块分 schema；关键表：assets（素材）、production_tasks（生产任务）、experts / expert_knowledge / mental_models（专家库）、content_facts / content_entities / content_beliefs（内容库）、meetings / mn_scopes / mn_runs（会议纪要）、workspaces / users / sessions（多租户账号）。行级安全（RLS）与 workspace 断言双重隔离。
  • 队列：Redis + BullMQ（会议分析 run、批量任务）。
  • LLM 路由：统一 Router 按 Key 可用性选择 Claude / Kimi / OpenAI / SiliconFlow / 火山引擎；CEO 模块支持 CEO_LLM_PROVIDER=claude-cli 走本机 Claude Code CLI（无需 Key）；Dashboard 场景走 /api/llm/chat/completions OpenAI 兼容网关。
  • 文件解析：.md/.txt/.docx/pdf（mammoth、pdf-parse、tesseract OCR、本地说话人切分解析器），上传上限 50MB。
  • 回调集成：飞书机器人卡片 webhook（默认 callbackUrl）与通用 HTTP 回调（HMAC-SHA256 签名，callbackSecret）。
  • OAuth：Google OAuth 登录。

1.9 非功能需求

  • 安全：会话 Cookie（cp_session）+ X-API-Key 双凭证；密码 bcrypt 存储；登录失败锁定 + 审计日志（admin/audit）；RLS 行级隔离；共享链接 token 鉴权；CORS 白名单。
  • 可靠：数据库初始化失败即退出（不静默降级）；迁移与种子幂等；孤儿 run 清理与管理接口；run 路由配置热重载。
  • 可观测：winston 结构化日志；/health /readyz 健康探针；各模块 health 与 _diagnostics 端点；AI 监测指标/报告/告警。
  • 性能：SSE 流式输出（长任务不阻塞）；上传 50MB 上限；读多写少接口均有列表分页；运行期性能索引保障。
  • 兼容：/api/v1/experts 旧版兼容；meeting-note-sources 旧路径 alias；api-key 凭证兼容期保留。

1.10 运维与部署

  • 进程：API 以 tsx src/server.ts 直跑（cwd=/newdata/pipeline/api），Worker 以 MN_WORKER_ONLY=true 独立进程；开发用 MN_API_ONLY=true 分离执行。
  • nginx：paper.morning.rocks vhost（80），静态 root=webapp/dist，/api 反代 3006，streaming 走 SSE 专用 location；CORS 头在 nginx 层统一注入。
  • 环境变量（api/.env）：DATABASE_URL/DB_*、ADMIN_API_KEY、COOKIE_SECRET、CLAUDE_API_KEY/KIMI_API_KEY/OPENAI_API_KEY、PUBLIC_API_BASE_URL、PORT=3006、DB_AUTO_MIGRATE、TAXONOMY_BOOTSTRAP、CEO_LLM_PROVIDER 等。

  • 发布：前端 tsc -b && vite build → dist；API 直接 tsx 热加载（生产以守护进程常驻）。

2.1 总览

Base URL

http://paper.morning.rocks        （生产，HTTP）
全部接口前缀：/api（如 /api/v1/production、/api/v3/health）
健康检查：GET /health  →  { status, service: "content-pipeline-api", version: "3.0.0" }

鉴权（二选一，共存）

方式说明
会话 Cookie登录后下发 cp_session Cookie；权限按用户/角色/工作区判定
X-API-Key请求头 X-API-Key: <ADMIN_API_KEY>；视为超管（api-key@local）。未配置 ADMIN_API_KEY 时兜底值为 dev-api-key-change-in-production；可用 AUTH_DISABLE_API_KEY 关闭

通用约定

  • 时间：ISO8601（UTC）；ID：UUID 或雪花字符串
  • 上传：multipart/form-data，单文件 ≤ 50MB
  • 流式：SSE（text/event-stream），nginx 对 /api/v1/streaming/ 关闭缓冲，读超时 3600s
  • 错误格式：{ "error": "...", "message": "...", "code": "ROUTE_NOT_FOUND" }；404 由全局 notFoundHandler 统一返回
  • 分页：列表接口支持 limit/offset（或 cursor），返回结构以各模块文档为准
  • 工作区：多租户接口按当前会话 workspace 过滤；跨租户访问返回 404（不泄露存在性）
